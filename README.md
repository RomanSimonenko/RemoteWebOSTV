# RemoteWebOSTV

Self-hosted веб-приложение для будущего управления телевизорами LG webOS из браузера.

Проект находится на стадии MVP. Основа приложения уже поддерживает создание одного владельца и вход. Сопряжение и команды ТВ появятся на следующем этапе после проверки на физическом устройстве; Docker-поставка пока не готова.

## Локальный запуск

Нужны Node.js 22.12+ и pnpm 11.15.1. Из корня репозитория:

```sh
pnpm install
pnpm build
export REMOTE_WEBOS_DATA_DIR="$(pwd)/.local/data"
export REMOTE_WEBOS_HOST=127.0.0.1
export REMOTE_WEBOS_PORT=8080
export REMOTE_WEBOS_PUBLIC_ORIGIN=http://127.0.0.1:8080
pnpm --filter @remote-webos-tv/api setup-token
pnpm --filter @remote-webos-tv/api start
```

Команда `setup-token` выводит одноразовый токен в терминал. Откройте адрес из `REMOTE_WEBOS_PUBLIC_ORIGIN`, введите токен и задайте имя и пароль владельца, затем войдите. Токен действует 15 минут; новый токен заменяет предыдущий. После создания владельца CLI больше не выдаёт токены. CLI и сервер должны использовать один и тот же абсолютный `REMOTE_WEBOS_DATA_DIR`. Храните этот каталог постоянно и ограничьте к нему доступ: там находятся SQLite и отдельный мастер-ключ авторизации. Не отправляйте токен в журналы или переписку.

## Конфигурация и HTTPS

- `REMOTE_WEBOS_DATA_DIR` — обязательный абсолютный путь к данным.
- `REMOTE_WEBOS_HOST` — обязательный адрес интерфейса сервера; для локального запуска `127.0.0.1`.
- `REMOTE_WEBOS_PORT` — обязательный TCP-порт от 1 до 65535.
- `REMOTE_WEBOS_PUBLIC_ORIGIN` — обязательный точный origin браузера: схема, хост и, при необходимости, порт; без завершающего `/` и пути. Для HTTPS пример: `https://remote.example.test`.
- `REMOTE_WEBOS_SECURE_COOKIES` — необязательное `true` или `false`; по умолчанию `true` для HTTPS. Для HTTPS-origin отключить Secure нельзя.
- `REMOTE_WEBOS_TRUSTED_PROXY` — необязательный список IP/CIDR доверенных прокси через запятую. Если не задан, заголовки переадресации не считаются доверенными.

Для доступа через HTTPS настройте TLS на своём reverse proxy, задайте `REMOTE_WEBOS_PUBLIC_ORIGIN` равным внешнему HTTPS-origin и передавайте в `REMOTE_WEBOS_TRUSTED_PROXY` только адреса действительно доверенных прокси. Браузер должен обращаться к API и странице с одного origin. Без HTTPS используйте только локальный или доверенный сегмент сети.

Сессия действует 24 часа с момента входа без продления. Сервер хранит её в SQLite; браузер получает только HttpOnly cookie с `SameSite=Strict` и `Path=/`. CSRF-токен запрашивается для текущей сессии и остаётся в памяти страницы. После истечения сессии нужно войти снова.

Проверка авторизации, в том числе `GET /api/auth/session`, удаляет обнаруженную истёкшую запись сессии. Это внутреннее обслуживание: действующие сессии, владелец и состояние ТВ не изменяются. Зафиксированное истечение сохраняется при откате часов и перезапуске; сессия с временем создания в будущем отклоняется до восстановления времени. Сервер не может обнаружить истечение, если часы откатились до его проверки.

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm --filter @remote-webos-tv/web exec playwright install chromium
pnpm --filter @remote-webos-tv/web test:e2e
```

Браузерная проверка использует временный каталог и создаёт только синтетического владельца. Перед ней нужен свежий `pnpm build`.
