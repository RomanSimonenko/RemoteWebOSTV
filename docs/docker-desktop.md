# Docker Desktop на Mac

Поставка предназначена для локального запуска рядом с webOS-ТВ. На Mac нужен запущенный Docker Desktop с Docker Compose. Образ собирается локально; опубликованного образа пока нет. Текущая установка автоматически не импортируется.

## Запуск

Из корня репозитория:

```sh
docker compose up -d --build
docker compose ps
docker compose exec app node apps/api/dist/src/auth/cli.js setup-token
```

Откройте http://127.0.0.1:8080, введите одноразовый токен, создайте владельца и войдите. Не отправляйте токен в чат, Git или журналы. Выпуск токена — отдельное действие, а не часть каждого запуска. После создания владельца новые токены не выдаются.

Если порт занят текущим приложением, сначала выберите другой порт, например:

```sh
export REMOTE_WEBOS_HTTP_PORT=8081
docker compose up -d --build
```

Откройте http://127.0.0.1:8081. Используйте то же значение переменной при последующих командах Compose. Она одновременно меняет публикацию порта и разрешённый origin браузера. Не используйте `localhost` вместо `127.0.0.1`: origin должен совпадать точно.

Добавьте ТВ по частному IP и подтвердите доступ на экране ТВ. Контейнер должен иметь сетевой доступ к телевизору. WOL из Docker Desktop проверяется отдельно: отсутствие ошибки отправки UDP не доказывает пробуждение ТВ. Автоматический поиск и удалённый домашний агент не входят в эту поставку.

### Включение по сети (WOL)

По умолчанию WOL отправляется на `255.255.255.255`, UDP-порт 9. Доставка broadcast из Docker Desktop зависит от сетевой конфигурации; для домашней подсети можно настроить адрес рассылки.

Задайте `REMOTE_WEBOS_WOL_BROADCAST_ADDRESS` равным broadcast-адресу **домашней сети ТВ**, рассчитанному по IP и маске сети, и пересоздайте контейнер с прежним именем проекта и volume. Не используйте broadcast внутренней сети Docker. Для примера: в тестовой подсети `192.0.2.0/24` адрес рассылки — `192.0.2.255`; это не адрес вашей сети.

Сохраняйте настройку в локальном окружении или исключённом из Git `.env` и используйте её при последующих обновлениях. При отсутствии настройки сохраняется прежний адрес; некорректный IPv4 останавливает запуск с ошибкой конфигурации. При изменении домашней подсети настройку необходимо обновить. После изменения проверьте реальное пробуждение ТВ кнопкой приложения: успешная отправка UDP сама по себе его не подтверждает.

## Ограничения проверки

Сохранность данных при пересоздании покрыта синтетическим Docker smoke. Перезапуск Docker Desktop, восстановление из резервной копии, Intel Mac и совместимость разных сетей/моделей требуют отдельной проверки.

## Данные и обновление

Именованный volume `app-data` содержит SQLite и оба мастер-ключа. Compose добавляет к имени volume префикс проекта. Не меняйте имя проекта или каталог запуска без понимания этого: другой проект может создать новое независимое хранилище.

Обычное обновление из проверенного состояния репозитория:

```sh
docker compose up -d --build
```

Для остановки:

```sh
docker compose stop
```

Пересоздание контейнера с тем же volume сохраняет данные. **Не выполняйте `docker compose down -v` для обычного обновления:** это удаляет данные установки. Не подключайте одновременно два сервера к одной SQLite.

Версия с несколькими webOS-ТВ автоматически переносит ранее сохранённый ТВ в новое хранилище: ID закрепляется один раз, IP, модель, версия ОС, MAC и зашифрованный ключ остаются прежними. Аккаунт и мастер-ключи не меняются. Пустая установка открывает пустой дашборд. Ошибка миграции блокирует запуск, не сбрасывая данные.

До такого обновления сохраните комплект данных по инструкции ниже. Старый образ несовместим с новой схемой: для отката остановите новую версию и восстановите её **предмиграционную** копию вместе с обоими мастер-ключами в отдельное выбранное хранилище. Добавленные после копии ТВ и другие изменения в эту копию не входят. Не запускайте старый образ поверх мигрированной базы.

## Резервная копия и перенос

Перед переносом или обновлением сделайте резервную копию всего хранилища, а не только SQLite. Она должна содержать `app.sqlite`, связанные файлы SQLite, `auth-master.key` и `tv-master.key`. Администратор Mac или Docker имеет доступ к этим данным; шифрование ключа ТВ не защищает от администратора хоста.

1. Остановите приложение через `docker compose stop`.
2. Скопируйте весь каталог данных из остановленного контейнера в выбранный защищённый каталог резервной копии: `docker compose cp app:/data/. <backup-directory>`.
3. Ограничьте доступ к копии: она содержит чувствительные данные. Не помещайте её в репозиторий или контекст Docker-сборки.
4. Запустите приложение через `docker compose start`.

Восстановление выполняйте только в отдельно выбранное хранилище остановленной установки. Сохраните содержимое назначения до замены; восстановите весь комплект файлов с правами runtime-пользователя, затем проверьте запуск и вход. Не смешивайте SQLite одной установки с ключами другой. Автоматический перенос существующей локальной установки этой инструкцией не выполняется.

## Безопасность и диагностика

Порт опубликован только на loopback Mac. Контейнер работает без root, дополнительных capabilities, privileged и доступа к Docker socket. Git, локальные данные, секретные файлы и служебные каталоги исключены из контекста сборки; параметры конкретного ТВ и аккаунт не входят в образ.

```sh
docker compose ps
docker compose logs --tail=100 app
```

Health проверяет API и хранилище. Выключенный ТВ не должен делать контейнер нездоровым. Ошибки отсутствующих ключей или недоступного хранилища не исправляйте удалением volume: сначала сохраните данные и выясните причину.

Автоматические проверки: `pnpm test:docker`. Они создают уникальные синтетические контейнеры, сеть и volume и удаляют только свои ресурсы. Настоящий ТВ и пользовательские данные не используются. Аппаратная совместимость Docker/WOL не объявляется подтверждённой этими тестами.
