## Питание/WOL в браузере — автоматическая проверка 2026-10-04

Tasks 1–4 приняты после независимых reviews. Новые семь Chromium-сценариев прошли узкий и полный прогон против собранного UI/API, настоящей авторизации и временной SQLite, Lgtv2Adapter и протокольного mock-TV. Проверены отмена подтверждения и единственный exact SSAP turnOff, нормализация/сохранение/очистка MAC после restart, двойное нажатие и две вкладки, ограниченное восстановление с сохранённым ключом без PROMPT, таймаут без новых циклов, потеря настоящего HTTP-ответа без replay и отмена владевшей сессии при logout.

Свежие результаты: `pnpm test` — 810/810 в 49 файлах на `7eeba36`; полный Chromium сначала дал 20/23 (три прежние синтетические проверки подготовки не имели ответа GET/api/tv/power). После одной строки в test-only фикстуре на `0e7b435` прошли свежие `pnpm typecheck`, `pnpm build`, полный Chromium — 23/23 (1,5 минуты, retries=0) и `git diff --check`. Код production и модульных тестов между этими checkpoints не менялся; 810 тестов не выдаются за новый прогон после исправления E2E. Все сборки выполнялись в независимой временной копии: первый чистый запуск выявил известную зависимость web typecheck от ещё не собранного API dist; после отдельной подготовки API полная сборка прошла. Ограничение документировано в README и остаётся открытой задачей графа сборки.

WOL в Chromium проверяет одну adapter.wake через внедрённый test-only транспорт; это не UDP-доставка. Отдельный интеграционный тест получил три полных magic packets через настоящий UDP на loopback и подтвердил закрытие отправляющего сокета. Назначение пакетов в этом тесте заменено на loopback receiver: результат не доказывает broadcast по LAN, сетевой режим контейнера или пробуждение физического ТВ. Отрицательный контроль неверного SSAP URI дал ожидаемый сбой сквозной проверки; правильный artifact восстановлен.

В автоматической фазе постоянные данные, живой сервер и физический ТВ не изменялись; все адреса, MAC и аккаунт тестов синтетические. Аппаратная приёмка выполнена отдельно после разрешения пользователя и автоматических проверок, как описано ниже; прежние CLI проверки не выдаются за доказательство нового браузерного пути.
