# Запуск через Docker Desktop на Mac

Дата: 2026-10-06. Статус: схема согласована; документ подготовлен для утверждения перед планом реализации.

## Цель и объём

Запуск существующего self-hosted приложения на Mac через Docker Desktop и Docker Compose. Один контейнер обслуживает Backend API и собранный веб-интерфейс. Телевизор находится в домашней сети и добавляется вручную по IP. Пульт, авторизация и протокольные контракты не меняются.

Этот этап не включает удалённый сервер, домашний агент, камеру, discovery или публикацию образа в реестре. Первая поставка собирается локально из репозитория; поддержка других систем и архитектур не объявляется без проверки.

## Образ и запуск

Многоэтапная сборка устанавливает зависимости по lockfile, собирает workspace и переносит в runtime только необходимые файлы и зависимости. Нативный SQLite-модуль собирается для Linux внутри образа; зависимости с macOS не копируются. Dockerfile и .dockerignore исключают локальные данные, секреты, Git, tooling и артефакты тестов.

Runtime запускает собранный сервер без сборки при каждом старте, от непривилегированного пользователя. Compose публикует порт только на loopback Mac: по умолчанию браузер открывает http://127.0.0.1:8080. Внутри контейнера сервер слушает доступный контейнерной сети интерфейс; внешний порт и точный public origin задаются согласованно. Публичный доступ и reverse proxy в этот этап не входят.

Используется обычная контейнерная сеть Docker Desktop, без privileged, Docker socket или предположения о Linux host networking. Проверка работоспособности оценивает API и хранилище, не доступность телевизора. Завершение контейнера должно корректно закрывать сервер и хранилище.

## Данные и первичная настройка

Отдельный именованный volume содержит SQLite, auth-master.key и tv-master.key. Сервер и команда setup-token используют один каталог и права доступа. Владелец явно запускает существующую CLI-команду внутри контейнера, затем создаёт аккаунт через браузер; токен не выводится при каждом запуске сервера и не сохраняется в образе или Compose.

Перезапуск и пересоздание контейнера с тем же volume сохраняют владельца, ключи и сопряжение. Инструкция объясняет резервное копирование всего хранилища вместе с обоими ключами и предупреждает, что удаление volume уничтожает данные. Автоматического импорта текущей установки нет.

Сначала проверяется чистая синтетическая установка с отдельным volume. Текущее приложение на Mac и его данные не меняются. Проверка нового приложения может использовать другой локальный порт с соответствующим origin. Переключение порта или перенос настоящих данных выполняются отдельно, после резервной копии и согласования; два сервера не открывают одну SQLite одновременно.

## Сеть и телевизор

Проверяется доступ из контейнера к включённому ТВ по частному IP и сохранённое повторное подключение. WOL остаётся существующей локальной UDP-командой: успешная отправка пакета не доказывает его прохождение через Docker Desktop и пробуждение экрана.

WOL проверяется отдельно с владельцем на физическом ТВ после автоматических тестов. При сетевом ограничении фиксируется фактический результат и понятное ограничение поставки; доставка не объявляется успешной без наблюдения. Привилегии, проброс портов роутера и обходы сетевой защиты автоматически не добавляются. Недоступность ТВ не делает контейнер нездоровым.

## Проверки и приёмка

1. Compose и образ проходят проверку конфигурации и чистую сборку на Mac.
2. Контейнер запускается без root; сервер и setup-token имеют доступ к одному постоянному каталогу.
3. Синтетическая установка позволяет создать владельца, войти и подключить тестовый ТВ через настоящий API.
4. Перезапуск и пересоздание с прежним volume сохраняют аккаунт и сопряжение; с новым volume показывается первичная настройка.
5. Повреждённые или недоступные данные дают явную ошибку запуска без тихого сброса ключей или аккаунта.
6. Проверка работоспособности проходит при недоступном ТВ; остановка не оставляет повреждённого хранилища.
7. В контекст и образ не попадают реальные данные, токены, локальные секреты и служебные каталоги.
8. После согласования аппаратного теста отдельно фиксируются соединение с настоящим ТВ и фактическое выключение/пробуждение через WOL.

Результат этапа — локально проверенная Docker-поставка и инструкция запуска, обновления, резервного копирования и ограничений сети. Перенос текущих данных и аппаратная проверка не считаются выполненными заранее.
