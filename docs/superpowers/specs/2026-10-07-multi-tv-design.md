# Несколько телевизоров в Smart TV Remote Hub

Статус: схема согласована; письменная спецификация ожидает проверки.

## Цель и границы

После входа пользователь видит сохранённые ТВ, добавляет устройства и открывает
пульт выбранного ТВ. Разные вкладки могут управлять разными устройствами.
Переключение не выключает ТВ, не разрывает его серверное соединение и не отменяет
уже принятую сервером операцию.

Этот этап реализует несколько LG webOS-ТВ на существующем адаптере. Samsung
Tizen, обнаружение устройств, камера, имена комнат, удаление ТВ и совместный
доступ нескольких владельцев не входят в этап. Samsung пользователя находится
в той же сети, работает на Tizen 9.0 и будет проверяться на следующем этапе.
Неподдерживаемая платформа отклоняется явно; интерфейс не обещает Tizen заранее.

## Пользовательский поток

1. Вход и перезагрузка страницы открывают дашборд; аккаунт не меняется.
2. «Добавить ТВ» доступно и при наличии сохранённых устройств.
3. Добавление открывает существующую форму частного IPv4-адреса и сопряжения.
   Только успешное сопряжение создаёт сохранённую карточку. Ошибка добавления
   не заменяет ранее добавленный ТВ и не удаляет его данные.
4. Карточка целиком кликабельна, с подсветкой при наведении/клавиатурном фокусе.
   В ней модель, платформа, доступная версия ОС и статус соединения. Нет IP,
   MAC, ключа сопряжения или искусственных демонстрационных устройств.
5. Пульт, настройки, питание/WOL и удержание кнопок относятся только к выбранному
   устройству. Недоступный ТВ тоже можно открыть для включения/переподключения.
6. «Телевизоры» возвращает к списку. Обработчики удержания и клавиатуры уходящего
   пульта прекращаются, вход пользователя в другой пульт не повторяет команды.
7. Настройки аккаунта остаются на дашборде; настройки ТВ не содержат строку
   «Вы вошли как». Подтверждения выхода и выключения сохраняются.

## Данные и безопасная миграция

Каждое устройство получает неизменяемый непрозрачный `tvId`, платформу `webos`,
канонический host, identity, зашифрованный ключ сопряжения и отдельный MAC.
Менять IP можно без смены `tvId`. Сортировка карточек стабильна по порядку
добавления, не зависит от скорости ответов телевизоров.

Новая версия миграции SQLite снимает ограничение единственной записи. Ранее
применённые миграции не переписываются. Существующий LG переносится транзакционно
с сохранением host, identity, версии ОС, MAC и существующего зашифрованного
конверта ключа. Мастер-ключ, аккаунт, пароль и сессии не меняются. Новый ID
сохраняется один раз и не пересоздаётся при рестарте.

Миграция пустой базы даёт пустой список. Ошибка откатывает транзакцию и блокирует
запуск: никакого сброса конфигурации или нового сопряжения вместо старых данных.
После миграции один репозиторий является источником истины; старое одиночное
хранилище не используется как скрытый резервный источник.

Перед обновлением сохраняется резервная копия базы и мастер-ключа. Откат на
старый образ после изменения схемы требует восстановления этой копии, а не
запуска старой версии поверх нового хранилища.

Дубли канонического IP запрещены, включая одновременно добавляемые адреса.
Смена адреса не может занять IP другой записи. Модель не является уникальным
идентификатором физического ТВ. Два адреса одного физического устройства без
надёжного аппаратного идентификатора автоматически не объединяются.

## Владение подключениями

Реестр устройств владеет отдельным экземпляром существующего TvService для
каждого `tvId`. Репозиторий передаёт ему только собственную запись. Адаптер,
состояние, операции, таймеры, восстановление и диагностика принадлежат этому
экземпляру, не общей переменной «активный ТВ».

При запуске сохранённые ТВ проходят существующую ограниченную процедуру
восстановления независимо. Сбой одного не блокирует запуск и управление другим.
Физическое включение/WOL не выполняется автоматически. Текущие бюджеты повторов,
таймауты и ограничения доставки не расширяются ради нескольких устройств.

Пульт выбирается локально в каждой вкладке. При уходе отменяются принадлежащие
экрану запросы/обработчики; это не команда отмены серверной операции.
Поздний ответ первого ТВ не обновляет пульт второго. При закрытии приложения
реестр закрывает все сервисы и освобождает их ресурсы, сохраняя ошибки очистки.

## HTTP и совместимость

Новые адресованные API используют существующие схемы статуса, ошибок, команд
и операций внутри явно определённого контекста ТВ:

| Путь | Назначение |
| --- | --- |
| `GET /api/tvs` | Список сохранённых устройств с ID, платформой и статусом |
| `POST /api/tvs` | Начать добавление webOS-ТВ; вернуть ID и принятую операцию |
| `GET /api/tvs/:tvId` | Статус выбранного устройства/процесса добавления |
| `/api/tvs/:tvId/operations` | Сопряжение/переподключение, смена адреса, ремонт доступа |
| `/api/tvs/:tvId/power`, `/api/tvs/:tvId/mac` | Питание и MAC выбранного устройства |
| `/api/tvs/:tvId/remote`, `/api/tvs/:tvId/commands` | Доступность пульта и адресованные команды |

Методы дочерних путей и пути отмены повторяют существующие операции. Возврат
202 означает принятую операцию, а не подтверждённый результат на экране ТВ.
Неверный ID возвращает 400, корректный неизвестный — 404; запрос не отправляется
первому или последнему ТВ вместо отсутствующего адресата.

Для добавления используется временный контекст, а не сохранённый фиктивный ТВ.
Он обслуживает проверку статуса и отмену до результата. Повтор той же заявки
с тем же ID в той же сессии не запускает новое сопряжение; изменение параметров
для этого ID отклоняется как конфликт. Терминальные неуспешные контексты
освобождаются при истечении сессии или через 10 минут после результата.
Работающий контекст сначала завершает отмену и очистку по существующим правилам;
остановка сервера закрывает все временные контексты. После освобождения клиенту явно сообщается отсутствие контекста,
без автоматического повторения заявки. Успешный контекст становится постоянным.

Старые `/api/tv/...` сохраняют формат и привязываются к постоянному совместимому
ID: перенесённому LG, а в новой пустой установке — первому успешно сохранённому
ТВ. Привязка сохраняется транзакционно при первом успешном сохранении и больше
не заменяется. Выбор в UI никогда не меняет её. До первого успешного добавления
сохраняется существующий одиночный сценарий начального сопряжения. Новая версия
интерфейса использует адресованные пути; общая логика не дублируется для старых.

Сессия, Origin, CSRF, no-store, проверка частного IPv4 и ограничения частоты
покрывают все новые пути и их кодированные варианты. Идемпотентность команд и
питания изолируется по сессии, `tvId` и ID запроса. Занятость одного ТВ не блокирует
другой; общие защитные лимиты сессии не ослабляются. Выход завершает принадлежащие
сессии операции по существующим правилам для всех затронутых устройств.

## Статусы и интерфейс

Дашборд читает список одним циклом опроса. Ошибка общего чтения не означает
пустой список; ошибки конкретного устройства относятся к его карточке.
При открытии пульта активен один источник его адресованного статуса; второй
параллельный цикл списка в этой вкладке не нужен. После возврата список обновляется.
Чтение списка не начинает новое сопряжение и не посылает WOL.

## Проверка готовности

- Миграция существующей/пустой базы, откат транзакции при ошибке, повторный запуск.
- Сохранение аккаунта, конверта ключа, MAC, identity и стабильного ID текущего LG.
- Два синтетических ТВ: отдельные команды, настройки, статусы и операции.
- Параллельные вкладки, одинаковые ID запросов у разных ТВ, общий выход из сессии.
- Добавление с ошибкой/потерей ответа, повтор заявки, дубли IP и смена адреса.
- Управляемые гонки: поздний статус, удержание при переходе, операция питания
  первого ТВ при работе со вторым. Ни одна команда не попадает другому устройству.
- Ошибки авторизации/сети, неизвестный ID и совместимость старых адресов.
- Ключи сопряжения, мастер-ключ и данные сессий не появляются в ответах и логах.
  IP/MAC доступны только в авторизованных настройках, не в карточке дашборда;
  тестовые логи и скриншоты используют синтетические данные.
- Узкий/широкий экран, клавиатурная навигация, сохранение списка после рестарта Docker.

Автоматические тесты используют синтетические ТВ и управляемое время. Ручная
проверка текущего LG выполняется отдельно с наблюдением пользователя. Реальная
работа Samsung и одновременное управление LG/Samsung не объявляются проверенными
до реализации адаптера Tizen и испытания обоих физических устройств.

## Почему выбран этот вариант

Одно глобально активное подключение проще, но нарушает независимость вкладок.
Отдельный процесс/контейнер на каждый ТВ добавляет развёртывание и обмен данными
без необходимости. Реестр независимых сервисов внутри текущего Node.js-приложения
сохраняет проверенный жизненный цикл webOS и изолирует адресацию устройств.
