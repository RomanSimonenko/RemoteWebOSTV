# Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development. Track each step below.

**Goal:** После входа открывать карточный дашборд с текущим ТВ и безопасным переходом к пульту.

**Architecture:** Home владеет выбором экрана. Единственный useTvStatus остаётся каноническим источником статуса и передаётся потребителям; пульт монтируется только на своём экране. Существующие серверные API, сопряжение и операции питания не меняются.

**Tech Stack:** React 19, TypeScript, Tabler, Vitest, Testing Library, Playwright; без новых зависимостей.

**Spec:** ../specs/2026-10-07-dashboard-design.md

## Global Constraints

- Первый этап: один сохранённый LG webOS-ТВ; никаких выдуманных устройств и обещаний поддержки Tizen.
- «Добавить ТВ» только в пустом состоянии; на карточке нет IP, MAC и ключей.
- Возврат к дашборду не выключает ТВ, не удаляет сопряжение и не отменяет серверную операцию.
- Ошибка чтения не означает отсутствие ТВ; команды настоящему ТВ не входят в автоматическую проверку.
- Текущие тёмная тема, Tabler, подтверждение выхода и правила питания сохраняются.

## Review Focus

- Потеря API при сохранённом ТВ: показать ошибку, не приглашать заново сопрягать.
- Переход во время операции: не отправлять отмену, при возврате прочитать актуальное состояние.
- Неактивный экран пульта: клавиатура не отправляет команды, попапы не перехватывают фокус.
- Истечение сессии на дашборде: переход к входу, прекращение опроса.
- Длинная модель и узкий экран: доступные действия без горизонтального скролла.

### Task 1: Дашборд и навигация на единственном источнике статуса

**Interfaces:** Dashboard получает `status: TvStatusResponse | null`, `loading: boolean`, `error: string`, `onOpenTv(): void`, `onAddTv(): void`, `onRetry(): void`. Home использует ветку с переданным источником статуса.
