# Docker Desktop на Mac: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Проверенный локальный запуск приложения через Compose с изолированными постоянными данными.

**Architecture:** Один многоэтапный образ содержит собранный API и веб-интерфейс. Compose публикует приложение только на loopback Mac; именованный volume сохраняет SQLite и оба мастер-ключа. Существующие API, CLI и управление ТВ не меняются.

**Tech Stack:** Docker Desktop, Docker Compose, Node.js 24 Debian slim, pnpm 11.15.1, существующий TypeScript workspace и better-sqlite3.

**Spec:** [Утверждённая схема](../specs/2026-10-06-docker-desktop-design.md).

## Global Constraints

- Один контейнер, непривилегированный runtime; без privileged, host networking и Docker socket внутри контейнера.
- По умолчанию http://127.0.0.1:8080; тестовый запуск использует свободный порт и соответствующий public origin.
- Текущая установка и реальные данные не меняются; автоматического импорта нет.
- Volume сохраняет SQLite, auth-master.key и tv-master.key вместе. Удаление volume не является обычным обновлением.
- Отдельный агент, камера, discovery и публикация образа вне этапа.
- WOL подтверждается наблюдением владельца, а не успешной отправкой UDP.

## Review Focus

- Занятый порт: настройка другого порта не нарушает origin/CSRF; проверка в задаче 2.
- Потерянный мастер-ключ при существующих данных: явный отказ, не создание новой установки; проверка в задаче 2.
- Новый volume: независимая первичная настройка без старого владельца; проверка в задаче 2.
- Локальные секреты и macOS node_modules: отсутствуют в контексте и образе; проверка в задаче 1.
- Выключенный ТВ и остановка контейнера: health остаётся корректным, данные сохраняются; проверка в задаче 2.

### Task 1: Образ и проверка упаковки

**Files:** создать `Dockerfile`, `.dockerignore`, `scripts/docker/smoke.mjs`; дополнить `package.json` командой `test:docker`.

**Interfaces:** образ запускает `node apps/api/dist/src/index.js`; CLI доступен как `node apps/api/dist/src/auth/cli.js setup-token`. Проверка `node scripts/docker/smoke.mjs` использует отдельный тестовый контейнер и volume с уникальным именем, очищает только созданные ей ресурсы в finally и возвращает ненулевой код при нарушении контракта.

### Task 2: Compose, данные и эксплуатационная проверка

**Files:** создать `compose.yaml`, `docs/docker-desktop.md`; расширить `scripts/docker/smoke.mjs`; обновить `README.md`, `docs/README.md` и дорожную карту.

**Interfaces:** сервис `app`, volume `app-data`, каталог `/data`; `REMOTE_WEBOS_HOST=0.0.0.0`, внутренний порт 8080, `REMOTE_WEBOS_DATA_DIR=/data`. Переменная Compose `REMOTE_WEBOS_HTTP_PORT` задаёт loopback-публикацию и origin `http://127.0.0.1:<port>` согласованно. Healthcheck использует существующий `/api/health`, без запроса к ТВ. Команда настройки: `docker compose exec app node apps/api/dist/src/auth/cli.js setup-token`.

- [ ] Расширить smoke: создать синтетического владельца через настоящие setup/login API, сохранить cookie только в памяти, пересоздать контейнер с прежним volume, проверить вход и неизменность обоих ключей. Новый volume должен возвращать первичную настройку.
- [ ] Добавить сохранение синтетической настройки ТВ через существующий mock-TV и настоящий защищённый API; после пересоздания проверить прежнюю модель и повторное подключение без нового сопряжения. Mock доступен только в тестовой сети, не в продуктовой Compose.
- [ ] Проверить на отдельном тестовом volume недоступное хранилище и потерю мастер-ключа: явный отказ без сброса владельца. Проверить health при недоступном mock-TV и сохранность после SIGTERM.
- [ ] До создания Compose выполнить проверку конфигурации и увидеть ожидаемый отказ из-за отсутствующего файла. Затем реализовать сервис, volume, healthcheck, loopback binding и остановку с достаточным grace period; права каталога доступны runtime-пользователю без root entrypoint.
- [ ] Проверить `docker compose config --quiet`, запуск на другом свободном порту, setup/login с верным origin и отказ мутации с посторонним origin. Занятый порт должен приводить к явной ошибке запуска, не изменению текущего приложения.
- [ ] Написать инструкцию локальной сборки, настройки, остановки, пересоздания, резервной копии и восстановления всего volume. Явно предупредить про `down -v`, доступ администратора Docker к данным и непроверенный WOL; не предлагать перенос живой SQLite.
- [ ] Выполнить полный `pnpm test`, `pnpm typecheck`, `pnpm build`, Docker smoke и существующий браузерный набор. В отчёте отделить реально выполненное от недоступных проверок.
- [ ] Согласовать отдельный аппаратный тест включённого ТВ и WOL с владельцем; не посылать питание автоматически. Если broadcast Docker Desktop не доставляется, документировать ограничение без обходов.
- [ ] Коммит `build: add Compose delivery and persistent data checks`; обновить результаты этапа в документации. PR и слияние только после отдельного разрешения.

## Граница завершения

**Результат 2026-10-06:** образ, Compose и автоматические проверки реализованы (коммиты `719ee60`, `112999b`). Конфигурация WOL не меняет адрес по умолчанию; невалидный IPv4 отклоняется при запуске. Исправлены промежуточные сообщения пульта при операциях питания. Подробности автоматической проверки и технических ограничений приведены в [инструкции Docker](../../docker-desktop.md) и [отчёте совместимости](../../compatibility/lg-43up76906le-webos-6.5.3.md). Исходные пункты выше — последовательность выполнения; ограничения результата не следует выводить из их чекбоксов. Перезапуск Docker Desktop, Intel Mac и восстановление резервной копии ещё не приняты; отрицательный контейнерный тест потери ключа выполнен для auth-master.key, не отдельно для tv-master.key.

Этап готов после чистой сборки и проверок контейнерного запуска, изоляции и сохранения данных на Mac. Аппаратный WOL, если не проверен или не работает, остаётся явно отмеченным ограничением, а не заявленной возможностью Docker-поставки. Текущая установка не переносится этим планом.
