## Цель

Получить проверенный на LG 43UP76906LE с webOS TV 6.5.3 self-hosted MVP: один Docker-контейнер, один владелец, один телевизор, управление из браузера, локальный доступ и возможность безопасной публикации через внешний HTTPS-туннель.

## Почему работа разделена на этапы

Протокол LG не является стабильным публичным контрактом, а совместимость зависит от прошивки и разрешений manifest. Поэтому сначала отдельно проверяется реальный телевизор. Последующие этапы используют только подтверждённый интерфейс `webOS Adapter` и не зависят от внутреннего API выбранной библиотеки.

## Этапы

### Этап 0. Протокольная проверка

Подробный план: `docs/superpowers/plans/2026-09-02-webos-protocol-validation.md`.

Результат:

- зафиксированная версия `lgtv2`;
- типизированная граница `webOS Adapter`;
- детерминированный mock-TV;
- диагностическая CLI-команда без утечки секретов;
- отчёт по LG 43UP76906LE;
- решение: использовать `lgtv2` напрямую через adapter, поддерживать минимальный fork либо реализовать нужную часть SSAP самостоятельно.

Шлюз перехода: сопряжение, повторное подключение и базовая команда должны работать на физическом телевизоре. При провале этап не маскируется: фиксируется конкретная несовместимость и сначала меняется протокольная реализация.

2026-10-01 шлюз пройден: выбран `lgtv2@2.0.0` через adapter, HOME подтверждена пользователем. [Аппаратный отчёт](../../compatibility/lg-43up76906le-webos-6.5.3.md) фиксирует результаты и непроверенные функции. Полный этап 0 требует завершения оставшихся аппаратных проверок и задачи 9.

### Этап 1. Основа приложения и безопасность

Результат:

- pnpm workspace с приложениями `api` и `web`, общими контрактами и модулем `webos`;
- Fastify API, React/Vite UI и SQLite;
- транзакционные миграции;
- состояние `unclaimed`;
- одноразовый установочный токен, создаваемый CLI-командой;

- шифрование `client-key` отдельным мастер-ключом;
- безопасная конфигурация и редактирование секретов в журнале.

Шлюз перехода: неавторизованный клиент не читает конфигурацию и не выполняет команды; перезапуск сохраняет владельца и сессии согласно контракту; миграционные и криптографические тесты проходят.

2026-10-03 основа приложения принята: [план и результаты](2026-10-01-app-foundation.md). Создание владельца, вход, постоянные сессии, CSRF/Origin, ограничение попыток, миграции и браузерные экраны реализованы. Повторно прошли 246 тестов, typecheck, build и Chromium E2E. Шифрованное файловое хранилище ключа обслуживает protocol probe; на момент приёмки основы сохранение client-key в SQLite и интеграция TV Service ещё оставались задачами этапа 2, теперь они выполнены в его первом вертикальном шаге. HTTPS-прокси в реальном развёртывании не проверен.

### Этап 2. Жизненный цикл телевизора и Backend API

Результат:

- ручное добавление ТВ по IP как обязательный надёжный путь;
- SSDP/mDNS discovery как дополнительный путь;
- сопряжение с тайм-аутом и отменой;
- сохранение ключа только после `registered`;
- Connection Manager с явной машиной состояний;
- повторное подключение без повторной отправки команд с неизвестным результатом;
- команды SSAP, pointer-сокет, приложения, входы, текст, уведомления;
- Wake-on-LAN с сохранённым MAC;
- REST/WebSocket API и диагностический снимок.

Шлюз перехода: API проходит интеграционные сценарии с mock-TV, а базовый набор команд повторно проверен на физическом телевизоре.

2026-10-03 завершён первый вертикальный шаг: [план и результаты ручного сопряжения](2026-10-03-tv-pairing.md). На исходном коде `8489cb9` прошли 447 тестов, typecheck, build и 8 Chromium E2E; финальное независимое review принято без блокирующих замечаний. На LG 43UP76906LE пользователь подтвердил браузерное сопряжение, сохранение после обновления страницы и повторного входа, подключение после перезапуска production-сервера с теми же данными без нового запроса доступа. При выключенном ТВ браузер сохранил настройку и показал потерю соединения; после включения явный reconnect прошёл без нового запроса доступа. Это ручные подтверждения и наблюдение браузерного экрана, без автоматической съёмки ТВ; границы зафиксированы в [аппаратном отчёте](../../compatibility/lg-43up76906le-webos-6.5.3.md). Изменения слиты в `main` через PR #3 (`5763ed4`). Discovery, команды пульта через API/UI, фоновый reconnect/backoff, WebSocket API и WOL UI остаются дальнейшей работой; шлюз всего этапа 2 этим шагом не закрыт.

## Неизменяемые границы

- Браузер обращается только к Backend API и никогда не получает `client-key`.
- Единственный владелец протокольных деталей — `webOS Adapter`.
- Состояния и ошибки нормализуются до продуктовых контрактов до выхода из adapter.
- Команды с неизвестным результатом не повторяются автоматически.
- Реальный IP, MAC, ключ сопряжения, cookie и пароль не попадают в репозиторий, отчёты или обычные журналы.
- Выключенный телевизор не делает контейнер нездоровым.
- Передача изображения и реалистичный дизайн пульта остаются вне MVP.
