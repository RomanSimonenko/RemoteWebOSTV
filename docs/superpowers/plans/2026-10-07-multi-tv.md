# Independent Multi-TV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Добавлять несколько webOS-ТВ и управлять каждым независимо из дашборда.

**Architecture:** Реестр владеет отдельным TvService и адресованным репозиторием каждого устройства. UI хранит выбор только внутри вкладки; старый API использует постоянную совместимую привязку. Существующий протокол webOS и правила доставки команд сохраняются.

**Tech Stack:** TypeScript, Node.js >=22.12.0, pnpm 11.15.1, Fastify, SQLite/better-sqlite3, React, Vitest, Playwright; без новых зависимостей.

**Spec:** ../specs/2026-10-07-multi-tv-design.md

## Global Constraints

- На этом этапе только `webos`; Tizen, discovery, камера, удаление ТВ и несколько владельцев исключены.
- Неизменяемый непрозрачный `tvId`; смена IP не меняет ID.
- Сохранить текущие аккаунт, сессии, MAC и зашифрованный конверт ключа LG.
- Ошибка миграции блокирует запуск; не сбрасывать данные и не переписывать старые миграции.
- Переключение экрана не выключает ТВ, не закрывает соединение и не отменяет принятую серверную операцию.
- Никакого автоматического WOL, повторной отправки неизвестного результата команды или увеличения бюджетов восстановления.
- Неуспешный терминальный контекст добавления хранится 10 минут либо до окончания сессии; работающий сначала безопасно завершает очистку.
- Legacy `/api/tv` привязан к перенесённому LG или первому успешно сохранённому ТВ, не к текущему выбору UI.
- Только синтетические значения в тестах/артефактах; физические проверки выполняет пользователь.

## Review Focus

1. Одновременное добавление одинакового IP: принять только одну заявку — task 3.
2. Перезапуск между сохранением ТВ и ответом HTTP: не потерять устройство/совместимую привязку — task 2, 4.
3. Ответ старого экрана после перехода: не изменить состояние нового ТВ — task 5.
4. Logout во время ожидания ограничителя: не отправить команду после отзыва сессии — task 4.
5. Ошибка закрытия одного адаптера: всё равно освободить остальные, сохранить причинную диагностику — task 3.

## Структура файлов

- `packages/contracts/src/tv-devices.ts`: ID, дескриптор списка, заявка добавления и её ответ; экспорт через `src/index.ts`.
- `apps/api/src/storage/migrations.ts`: следующая миграция многозаписного хранилища.
- `apps/api/src/tv/device-repository.ts`: список записей, постоянная legacy-привязка, адресованные фасады существующего TvRepository.
- `apps/api/src/tv/device-registry.ts`: жизненный цикл сервисов и временных контекстов.
- `apps/api/src/tv/device-routes.ts`: список/добавление и общий выбор адресата.
- `apps/api/src/tv/{routes,command-routes,power-routes}.ts`: существующая логика маршрутов для адресованного и legacy-контекста без копирования.
- `apps/api/src/{runtime,app}.ts`, `security/http-policy.ts`, `tv/rate-limit.ts`: сборка, безопасность и общие лимиты.
- `apps/web/src/{api,useTvStatus}.ts`, `pages/{Home,Dashboard,TvSetup}.tsx`: адресация и выбор экрана; существующие компоненты пульта/питания получают адресованный API.
- `apps/web/src/useTvDevices.ts`: один опрос списка на дашборде.
- Тесты рядом с существующими тестами соответствующей границы; новые `tv-devices`, `tv-device-repository`, `tv-device-registry`, `tv-device-routes`, `useTvDevices`.

До изменения сигнатур проследить всех вызывающих через `graft callers <symbol> --depth all`, включая компоненты пульта, питание, тестовые harness и security-policy. Не считать перечень выше разрешением пропустить найденных потребителей.

## Task 1: Контракты адресации

**Files:** создать `packages/contracts/src/tv-devices.ts`, `test/tv-devices.test.ts`; изменить `src/index.ts`.

**Interfaces:**
- `tvIdSchema`: UUID; `TvId` — его выведенный тип.
- `TvDevice`: `{ tvId: TvId; platform: 'webos'; status: TvStatusResponse }`, где status содержит только существующую публичную проекцию без ключа.
- `tvDevicesResponseSchema`: `{ devices: TvDevice[] }`.
- `addTvRequestSchema`: строгий `{ id: UUID; platform: 'webos'; host: TvHost }`, используя существующий канонизатор частного IPv4.
- `addTvResponseSchema`: `{ tvId: TvId; operation: TvOperation }`.

- [ ] Написать тесты `acceptsCanonicalWebosDevice`, `rejectsTizenAndUnknownFields`, `rejectsInvalidIdAndNonPrivateHost`, `rejectsSecretFields`; assertions: корректный UUID проходит, `platform: 'tizen'`, лишний ключ и публичный IP отклоняются, ключ сопряжения не входит в публичную схему.
- [ ] Запустить `pnpm --filter @remote-webos-tv/contracts test -- test/tv-devices.test.ts`; подтвердить FAIL из-за отсутствующих схем.
- [ ] Реализовать схемы через существующие схемы ID/host/status/operation, без второго IPv4-парсера.

**Interfaces:** `TvDeviceRegistry`:
