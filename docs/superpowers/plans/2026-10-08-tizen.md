# Samsung Tizen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавлять и одновременно подключать LG webOS и Samsung Tizen, управляя выбранным ТВ без влияния на соседние устройства.

**Architecture:** Общий контракт управления отделяется от LG-протокола. Реестр выбирает отдельный TypeScript-адаптер по платформе; сервис остаётся владельцем операций, авторизации и сериализации. Samsung использует WebSocket внутри того же Node.js-процесса.

**Tech Stack:** TypeScript, Node.js, ws, SQLite/better-sqlite3, Zod, React, Vitest, Playwright. Версии существующих зависимостей не обновлять ради этого этапа.

**Spec:** `docs/superpowers/specs/2026-10-08-tizen-design.md`

## Global Constraints

- Несколько независимых соединений: выбор карточки не закрывает остальные ТВ.
- Сохранить tvId, ключи LG, MAC, порядок и устройство по умолчанию.
- Не сохранять частные адреса, реальные MAC и токены в исходниках/фикстурах/логах.
- Samsung WSS:8002; исключение доверия self-signed только в локальном Samsung-транспорте, без глобального TLS bypass и WS fallback.
- Не выдавать версию API за версию Tizen; нет достоверной версии ОС — badge только Tizen.
- Не обещать Wink, источники, приложения или питание Samsung до проверки поддержки.
- Команды питания и реальные клавиши только после отдельного согласия владельца; видимый эффект проверяет владелец/камера.
- Узкие экраны вне объёма; камера и LG не должны регрессировать.
- Каждая задача: сначала красный тест, минимальная реализация, зелёный тест, проверка типов, отдельный коммит. Не менять тесты ради сокрытия дефекта.

## Review Focus

1. Поздний connect после отмены не сохраняет токен — Task 3.
2. Одинаковые operation id на двух платформах не смешивают команды и квитанции — Task 4.
3. Старые encrypted LG credentials после миграции читаются тем же master key — Task 2.
4. Переключение ТВ при удержании останавливает старый repeat, не переносит его на новое устройство — Task 5.
5. Отозванный Samsung token не вызывает автоматических новых запросов разрешения — Tasks 3/6.

### Task 1: Общий контракт адаптера без фиктивного pointer

**Files:** создать `packages/tv-adapter/{package.json,tsconfig.json,src/index.ts}`; изменить `packages/webos/src/adapter.ts`, `packages/webos/src/lgtv2-adapter.ts`, `packages/contracts/src/tv.ts`, потребителей в `apps/api/src/tv/service.ts`; тесты `apps/api/test/tv-service.test.ts`, `apps/api/test/tv-command-routes.test.ts`.

**Interfaces:** `TvAdapter` с `pair(request: PairingRequest): Promise<PairingResult>`, `readSnapshot(signal: AbortSignal): Promise<TvSnapshot>`, `prepareRemote(signal: AbortSignal): Promise<void>`, `sendButton(button: TvButton, signal: AbortSignal): Promise<void>`, `disconnect(): Promise<void>`. Дополнительные методы остаются optional и gated capabilities. `PairingRequest` принимает `host`, `credential?: string`, `signal`; `PairingResult` возвращает `credential`, `identity`, `capabilities`, `transport`, `macAddresses`. Добавить платформенно нейтральную capability `buttons`; не использовать `pointer` как признак Samsung-пульта. LG `prepareRemote` открывает его pointer socket.

- [ ] Добавить `buttonsWithoutPointerCanPrepareAndSend`: адаптер с `buttons=true,pointer=false` позволяет UP; `unsupportedButtonsSendNothing`: `buttons=false` отклоняет UP. Existing LG tests должны оставаться зелёными.
- [ ] Выполнить `pnpm --filter @remote-webos-tv/api exec vitest run test/tv-service.test.ts test/tv-command-routes.test.ts`; увидеть ожидаемое падение нового случая.
- [ ] Вынести только общий контракт; адаптировать LG и владельца remote readiness. Обновить все потребители через `graft callers ... --depth all`, не создавать Samsung no-op pointer.
- [ ] Повторить тесты, `pnpm typecheck`; сохранить обратную совместимость текущих transport/capability payloads при добавлении новых значений, не переименовывать публичные поля без миграции.
- [ ] Коммит `refactor: introduce platform-neutral TV adapter boundary`.

### Task 2: Платформа и зашифрованная авторизация в хранилище

**Files:** `packages/contracts/src/{tv.ts,tv-devices.ts,tv-setup.ts}`, `apps/api/src/{storage/migrations.ts,tv/repository.ts}`, `apps/api/test/{tv-device-repository.test.ts,tv-storage.test.ts}`; использовать существующий storage harness.

**Interfaces:** `TvPlatform = 'webos' | 'tizen'`; `StoredTv` — discriminated union по platform с encrypted credential. `TvDeviceRepository.list()` возвращает обе платформы. `forDevice(tvId)` сохраняет привязку к одному устройству. Legacy `/api/tv` остаётся привязан к default tvId, не становится broadcast.

- [ ] Тест `migrationPreservesLgAuthorizationAndDefault`: создать предыдущую схему штатными migrations, записать синтетический LG encrypted key, upgrade, проверить прежние id/order/default/MAC и расшифрование. `mixedPlatformsRoundTrip`: записать LG и Samsung, restart, прочитать оба; malformed platform/token отклоняются.
- [ ] Запустить соответствующие repository/storage тесты и увидеть RED.
- [ ] Добавить следующую штатную транзакционную миграцию с backup-before-upgrade. Преобразовать старое webOS credential в новый внутренний union без расшифрования в SQL/логах; использовать существующий cipher. Не менять существующие ответы клиентов без необходимости.
- [ ] GREEN repository/storage + contracts tests; `pnpm typecheck`; проверить fail-closed старой версии и отсутствие потери записей при ошибке миграции.
- [ ] Коммит `feat: persist platform-specific TV authorization`.

### Task 3: Samsung transport и протокол

**Files:** создать `packages/tizen/{package.json,tsconfig.json,src/index.ts,src/samsung-adapter.ts,src/response-parsers.ts,test/samsung-adapter.test.ts,test/support/mock-samsung.ts}`.

**Interfaces:** `createSamsungAdapter(dependencies): TvAdapter`; dependencies включают HTTP/WebSocket factory, scheduler, локальную policy адреса; время и сетевые ответы управляемы тестом. Credentials — opaque token, wire сериализация валидируется по реальному сообщению, не по предположению.

- [ ] Сначала получить новый реальный connect sample без вывода token; сохранить только синтетическую копию его структуры. Проверить endpoint и command envelope по первичному исходнику протокола до реализации sendButton.
- [ ] Добавить тесты `connectEventCommitsToken`, `socketOpenIsNotPairSuccess`, `unauthorizedStopsWithoutReprompt`, `lateConnectAfterAbortDoesNotCommit`, `malformedPayloadFailsSafely`, `disconnectReleasesTimers`, `tlsExceptionDoesNotAffectOtherClients`. Assertions: credential только после valid connect, ноль commits после abort, ноль повторов команды при потере ответа.
- [ ] RED: `pnpm --filter @remote-webos-tv/tizen test`.
- [ ] Реализовать HTTP identity, WSS connect/token reuse, проверку sender/connection ownership, cancellation/cleanup и literal map поддержанных клавиш. `readSnapshot` выдаёт только фактически доступные сведения; неподдержанные LG поля отсутствуют. Не реализовывать фиктивные успешные apps/inputs/power.
- [ ] GREEN той же командой; `pnpm typecheck`; mock должен проверять точные исходящие Samsung frames, отказ и повторное подключение.
- [ ] Коммит `feat: add Samsung Tizen protocol adapter`.
