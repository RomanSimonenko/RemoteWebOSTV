# Назначение продукта и визуальная обратная связь

Дата: 2026-10-06.
Статус: согласовано пользователем 2026-10-06; формулировки перенесены в README, основное ТЗ, roadmap и спецификацию интерфейса. Реализация камеры и публикация изменений — отдельные шаги.

## 1. Основное назначение

Smart TV Remote Hub — self-hosted веб-приложение для управления и тестирования Smart TV. Пользователь отправляет команды из браузера и проверяет реакцию настоящего телевизора. Приложение предназначено для использования в качестве тестового стенда, а не только бытового дистанционного пульта.

Сейчас поддерживается один LG webOS-ТВ. Планируются Samsung Tizen и дашборд нескольких телевизоров разных платформ: выбор устройства, управление и тестирование, затем переход к другому ТВ. Эти возможности пока не реализованы. Внешняя камера остаётся отдельным планируемым расширением.

## 2. Запланированное расширение: вебкамера рядом с пультом

На экране приложения планируется показывать видеопоток с вебкамеры рядом с виртуальным пультом. Камера направлена на экран физического телевизора. Это позволит наблюдать визуальную обратную связь от ТВ после нажатия кнопок в приложении: перемещение фокуса, открытие экранов, изменение отображаемого содержимого и другие видимые реакции.

Базовый пользовательский цикл:

1. Пользователь нажимает кнопку виртуального пульта.
2. Приложение отправляет команду телевизору через существующий защищённый путь.
3. Пользователь наблюдает реакцию телевизора в видеопотоке рядом с пультом.
4. Пользователь сопоставляет фактическую реакцию с ожидаемой при ручном тестировании.

Источник изображения — внешняя вебкамера, а не встроенный захват экрана webOS. Поток показывает физический экран и может иметь задержку. Успешная отправка команды, наличие соединения и визуальное подтверждение результата — разные события: первое не доказывает последнее. Отсутствие видимой реакции само по себе не доказывает неуспех команды.

## 3. Границы и статус

- Управление ТВ реализовано; интеграция видеопотока вебкамеры пока только планируется.
- Видеопоток — средство наблюдения и фиксации визуальной обратной связи в интерфейсе, а не обещание записи видео на диск.
- Запись видео, сохранение снимков, журнал с привязкой кадров к командам и автоматическое распознавание/оценка результатов не входят в это согласование. Их можно спроектировать отдельно.
- Камера не должна включаться автоматически или скрытно. Пользователь явно включает просмотр и может его остановить; активный поток должен быть обозначен в интерфейсе.
- Изображение с камеры может содержать частную информацию. Доступ должен быть ограничен владельцем установки; запись, публикация и передача третьим сторонам по умолчанию не предполагаются.
- Тип подключения камеры, размещение источника потока, протокол доставки, допустимая задержка и окончательная адаптивная компоновка определяются при отдельном проектировании. Сейчас они не фиксируются.
- Self-hosted архитектура, авторизация, хранение ключа сопряжения на сервере и безопасность команд остаются без изменений.
- Текущий объём MVP не расширяется автоматически: видеопоток выделяется в отдельный будущий этап. Его место в очереди работ согласуется отдельно.

## 4. Предлагаемые изменения существующих документов

### README.md — вводное описание

Заменить вводную формулировку на:

> Open-source self-hosted веб-приложение для управления и тестирования телевизоров под управлением webOS из браузера. Основное направление развития — тестовый стенд: виртуальный пульт и запланированный видеопоток с вебкамеры рядом с ним для наблюдения реакции физического ТВ после команд. Видеопоток пока не реализован.

Добавить раздел «Тестовый стенд и визуальная обратная связь» с назначением, циклом ручной проверки и границами из разделов 2–3 этого предложения.

### Основное ТЗ — назначение, цели и границы

В разделе «Назначение» зафиксировать управление и тестирование webOS-ТВ как основной сценарий. В целях явно разделить подтверждение доставки команды и наблюдение фактической реакции телевизора.

В разделе «Не входит в MVP» уточнить, что прямой захват изображения/звука с ТВ и скриншоты webOS остаются вне текущего объёма. Видеопоток внешней вебкамеры также пока вне MVP, но является запланированным отдельным расширением тестового стенда, а не отвергнутой функцией.

### Roadmap — отдельное планируемое направление

Добавить будущий этап «Визуальная обратная связь с вебкамеры»: явное включение/остановка просмотра, отображение потока рядом с пультом, ручное наблюдение реакции ТВ и обработка недоступности камеры без нарушения управления. Перед реализацией согласовать источник потока, доставку и критерии приёмки. Порядок этапа относительно оставшихся функций пульта и поставки не менять без отдельного решения.

### Спецификация интерфейса — будущая компоновка

Отметить, что текущая компактная карточка пульта сохраняется. В дальнейшем основной экран должен допускать размещение видеопотока вебкамеры рядом с пультом на компьютере. Конкретный макет и поведение на узких экранах будут согласованы отдельно; текущая вёрстка этим документом не меняется.

## 5. Решение для согласования

Утвердить назначение «управление и тестирование webOS-ТВ» и запланированное расширение «видеопоток внешней вебкамеры рядом с пультом», без включения записи и автоматизации тестов в текущий объём. После согласования перенести изменения в перечисленные документы. Коммит и PR выполняются отдельным шагом.
